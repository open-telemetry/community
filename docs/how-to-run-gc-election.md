# How to run a Governance Committee election

This runbook covers the end-to-end process for running an OpenTelemetry
Governance Committee (GC) election. It is written for the election committee
(the `@open-telemetry/otel-elections` team). For the voter-facing view of a
specific cycle, see the per-year file under
[elections/\<year\>/governance-committee-election.md](../elections/).

## Scheduling the election

Aim for the voting window to end roughly **two weeks before KubeCon North
America**. That gives time to tabulate results, announce them, and onboard
the new GC members ahead of the OpenTelemetry events at KubeCon.

Work backwards from the target voting end date to pick:

* Nomination deadline (usually ~2 weeks before voting starts)
* Nominee list publication date (immediately after the nomination deadline)
* Voting window (3 days is customary; starts ~1 week after the nominee list
  is published)
* Results announcement (1–2 days after voting ends)

Record the chosen dates in the tracker issue (see below) and in the per-year
election document.

## Pre-election setup

Follow this checklist in order.

1. Determine election dates (nomination deadline, voting window, results
   date) per the schedule guidance above.
2. Confirm the election platform. We use [Helios Voting](https://vote.heliosvoting.org/).
3. Create the new election in Helios (see
   [Creating the Helios election](#creating-the-helios-election) below).
4. Update `@open-telemetry/otel-elections` team membership to reflect this
   cycle's election committee.
5. Create `elections/<year>/` directory in this repo:
   * `governance-committee-election.md` — adapted from the previous year,
     updated seats / dates / vacancies / committee.
   * `governance-committee-candidates.md` — empty candidates template.
6. Create a Google Form for voter-registration exemption requests. Link it
   from the tracker/announcements issue (see next step).
7. Create the GC Election Tracker / Announcements issue (see
   [Creating the announcements issue](#creating-the-announcements-issue)
   below). Add label `area/gc-election`.
8. Publish a blog post announcing the election and the call for
   nominations.

## Creating the announcements issue

Use the template below, adapted from
[#3677](https://github.com/open-telemetry/community/issues/3677). This issue
serves two purposes: it holds the eligible-voter list via `@`-mentions, and
it's where announcements about the election get posted.

```markdown
This issue will contain <YEAR> GC Election announcements and the complete
list of eligible voters. Subscribe to this issue if you wish to be notified
of changes. Contact @open-telemetry/otel-elections if you have questions.

If you are not [automatically detected as a member of standing](https://github.com/open-telemetry/community/blob/main/elections/<YEAR>/voters-roll.csv)
and believe your contributions should make you eligible to vote, you may
[request an exemption by filling out a registration form](<GOOGLE_FORM_URL>).

People mentioned in this issue have been detected as members of standing,
as [defined in the project's governance charter](https://github.com/open-telemetry/community/blob/main/governance-charter.md#members-of-standing).

You can find more information about the voting process [here](https://github.com/open-telemetry/community/blob/main/elections/<YEAR>/governance-committee-election.md).

Voting will be open between <START_DATETIME_UTC> and <END_DATE>, end of day,
[Anywhere on Earth](https://en.wikipedia.org/wiki/Anywhere_on_Earth)
(<END_DATETIME_UTC>) via the [voting link](<HELIOS_ELECTION_URL>).

Due to the potential notification storm that this issue may cause, the
conversation is locked. If you have concerns, please contact the group
@open-telemetry/otel-elections, or any of the members (@<member1>, @<member2>,
@<member3>) individually. They are also available on the [CNCF Slack](http://slack.cncf.io/).
```

After opening the issue, **lock the conversation** (right sidebar → Lock
conversation) to prevent a notification storm from inline replies.

The `@`-mentions in the issue body + follow-up comments are what notify
voters that they're eligible. Those comments are generated by the
`create-github-comments.py` script (see
[Voter roll generation](#voter-roll-generation) below).

## Creating the Helios election

Log into [vote.heliosvoting.org](https://vote.heliosvoting.org/) as an
election administrator and create a new election. You can use the [2026 election](https://vote.heliosvoting.org/helios/elections/9bad2b3c-d2df-4634-b801-a6926fdd2251/view)
as a reference and configure these settings:

| Setting | Value |
| --- | --- |
| Short name | `otel-gc-<year>` |
| Name | `OpenTelemetry Governance Committee <year>` |
| Description | Short paragraph referencing the per-year election doc |
| Election type | Election |
| Private? | **No** (public) |
| Help email | `cncf-opentelemetry-governance@lists.cncf.io` |
| Voting starts | Your chosen start datetime (UTC) |
| Voting ends | Your chosen end datetime (UTC) |
| Use voter aliases | No |
| Randomize answer order | Yes |

After creation, add one question:

* Question text: `Please vote for up to <N> candidates for the OpenTelemetry Governance Committee.`
* Minimum answers: `0`
* Maximum answers: `<number of seats>` (e.g. `4` when four seats are open)
* Answers: one per nominee (add after the nominee list is finalized — this
  can be done after voter upload)

Do **not freeze** the election yet. Voters cannot be uploaded via CSV in
bulk once the election is frozen in the UI's "add voters" flow, so wait
until after the voter roll is loaded.

## Voter roll generation

Scripts live in [scripts/gc-elections/](../scripts/gc-elections/). Full
usage docs for each script are in
[scripts/gc-elections/README.md](../scripts/gc-elections/README.md).

Run them in this order:

1. **Generate the voter roll:**

   ```bash
   export GITHUB_TOKEN=<a token with minimal permissions>
   python scripts/gc-elections/generate-voters-roll.py
   ```

   Produces `./voters-roll.csv` with GitHub logins and contribution counts.
   The script pulls from both CNCF DevStats and LFX Insights. Commit this
   as `elections/<year>/voters-roll.csv`.

2. **Tag eligible voters in the announcements issue:**

   ```bash
   # dry run first
   VOTERS_ROLL_PATH=elections/<year>/voters-roll.csv \
     python scripts/gc-elections/create-github-comments.py \
     -i <announcements-issue-url> -d true

   # then post for real
   VOTERS_ROLL_PATH=elections/<year>/voters-roll.csv \
     python scripts/gc-elections/create-github-comments.py \
     -i <announcements-issue-url> -d false
   ```

   The script is idempotent — if you regenerate the roll later and re-run,
   it only adds comments for newly added voters and removes `@`-mentions
   for voters no longer on the roll.

3. **Convert to Helios format:**

   ```bash
   VOTERS_ROLL_PATH=elections/<year>/voters-roll.csv \
     python scripts/gc-elections/convert-voter-roll-to-helios.py
   ```

   Produces `./voters-roll-helios.csv` with one `github,<handle>` row per
   voter.

## Uploading voters to Helios

In the Helios admin UI for your election:

1. Open the **Voters & Ballots** tab.
2. Click **Upload a file of voters**.
3. Upload `voters-roll-helios.csv`.
4. Helios shows a preview of the first few rows. Verify the format is
   `github,<handle>` for each row.
5. Click **Confirm** to actually commit the upload. **This step is
   required** — the voter rows are NOT created until Confirm is clicked.
6. Wait for the background job to finish; refresh the Voters tab to see
   the full roster.

Re-uploads are additive, not replacing. See the troubleshooting section
below for how to add individual voters mid-election.

## Finalizing and opening voting

Once the nominee list is final:

1. In the Helios admin UI, edit the question to add each nominee as an
   answer. Order will be randomized per-voter at voting time.
2. Freeze the election (**Freeze ballot for voting**). After freezing, the
   question text and nominee list cannot be changed. **Voter uploads and
   individual voter deletes are still allowed** on frozen elections, so
   mid-election voter adjustments are possible — see troubleshooting.
3. At the scheduled start time, voting opens automatically (Helios uses
   the voting-start timestamp you set at creation).
4. Send reminder emails via the governance mailing list
   (`cncf-opentelemetry-governance@lists.cncf.io`). Typically:
   * 1st reminder: when voting opens.
   * 2nd reminder: ~24 hours before voting closes.
   * 3rd reminder: ~2 hours before voting closes.

## Post-election

1. In the Helios admin UI, start tallying. This computes the encrypted
   tally.
2. Trustees release their decryption factors (coordinate out-of-band).
3. Combine decryption factors to produce the final result.
4. Apply charter tie-break rules if needed (e.g. the same-company limit
   from the governance charter).
5. Announce results via blog post, update the tracker issue with the
   link, and notify the governance mailing list.
6. Offboard departing GC members and onboard new members:
   * File a GC Member Onboarding issue for each new member.
   * Update `community-members.md` and CODEOWNERS.
   * Revoke system access for departing members.
   * Invite departing members to `#opentelemetry-gc-alum`.

## Troubleshooting

### Case 1 — Helios lost authorization; voter needs to re-authorize

**Symptom:** A voter clicks "Vote now", gets redirected to GitHub, and sees
a generic Helios error ("There was an error while handling your request")
or is bounced back to the election home page without being logged in.

**What to tell the voter:**

1. Open [github.com/settings/applications](https://github.com/settings/applications).
2. Find the **Helios Voting** entry under "Authorized OAuth Apps".
3. Click **Revoke access** (or revoke the app entirely).
4. In a fresh window, open the election URL and click
   **Vote now** → **Login with GitHub**. GitHub will prompt them to
   authorize Helios again — accept.
5. Proceed to vote.

### Case 2 — Voter with mixed-case GitHub handle can't log in

**Symptom:** A voter whose GitHub login contains uppercase letters (e.g.
`AwesomeUser`) clicks "Login with GitHub" and gets "There was an
error while handling your request", or logs in successfully but sees "not
registered to vote and registration is closed" when trying to cast.

**The workaround:** add them to the election as a Google voter instead.
They can then log in via Google using their email address.

Steps for the election committee:

1. Confirm with the voter which email address is on their Google account.
2. Prepare a one-row CSV in Helios bulk-voter format:

   ```csv
   google,<their.email@example.com>,<their.email@example.com>,<Full Name>
   ```

   Column meanings: `voter_type,voter_id,email,name`. For the `google`
   voter type, `voter_id` **must be the exact email Google OAuth returns**
   — case-sensitive, canonical form.

3. In the Helios admin UI, upload the one-row CSV via **bulk upload voters** and click **Confirm**.
4. Delete the voter's existing `github,<handle>` voter row from the
   Voters tab so they don't have two rows. (Voter deletion is allowed on
   frozen elections before tallying starts.)
5. Tell the voter to log in via the **Google** option on the Helios
   election page.
